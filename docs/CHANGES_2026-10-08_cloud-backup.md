# النسخ الاحتياطي السحابي — المرحلة 1 (2026-10-08)

## الفكرة

كل جهاز كاشير بيعمل نسخة كاملة من قاعدة البيانات (`pos.db`)، يشفّرها على الجهاز نفسه،
ويرفعها على سيرفر المحل **لما يكون فيه نت**. البيع عمره ما يستنى على النت ولا على الرفع.

- **إمتى بيرفع:** كل ساعة، ومع كل قفلة وردية (Z)، وزرار "إنشاء نسخة الآن".
- **لو مفيش تغيير** من آخر نسخة: مبيرفعش حاجة.
- **لو النت قاطع:** المحاولة بتفشل بهدوء، وبيحاول تاني بعد 5 دقايق.
- **طلبات Stress Lab** عمرها ما تطلع من الجهاز. لو موجودة، النسخ بيقف لحد ما تتمسح.

## التشفير

- مفتاح الاسترجاع (Recovery key) بيتعمل على أول جهاز: 32 بايت عشوائي، بيظهر كـ 52 حرف
  في مجموعات من 4 (مثلاً `7K2M-...`).
- النسخة بتتضغط (gzip) وبعدين بتتشفر AES-256-GCM قبل ما تطلع من الجهاز.
- **السيرفر عمره ما بيشوف المفتاح.** لو حد سرق السيرفر كله، النسخ ملهاش أي قيمة من غيره.
- **لو المفتاح ضاع، النسخ كلها تضيع.** لازم المالك يكتبه ويحفظه بعيد عن الجهاز
  (الإعدادات ← النسخ الاحتياطي السحابي ← عرض مفتاح الاسترجاع).
- فيه مفتاح واحد لكل محل. أول نسخة بتثبّت مفتاح المحل على السيرفر. أي جهاز تاني بيتربط
  بعد كده لازم يتكتب فيه نفس المفتاح، والسيرفر بيرفض أي نسخة بمفتاح مختلف.
- توكن الجهاز ومفتاح الاسترجاع محفوظين في keychain الجهاز (Windows Credential Manager)،
  **مش** جوه `pos.db`، علشان ميسافروش مع كل نسخة.

## على الجهاز (Flutter)

| الملف | الدور |
| --- | --- |
| `lib/core/cloud/recovery_key.dart` | مفتاح الاسترجاع: التوليد، والكتابة/القراءة بحروف Crockford، و`id` قصير بيعرّف المفتاح من غير ما يكشفه |
| `lib/core/cloud/backup_envelope.dart` | تغليف النسخة: gzip ثم AES-256-GCM، وبيشتغل في isolate منفصل علشان الشاشة متقفش |
| `lib/core/cloud/cloud_client.dart` | الكلام مع السيرفر: ربط الجهاز، رفع، قائمة النسخ، تحميل |
| `lib/core/cloud/cloud_secrets.dart` | التوكن والمفتاح في الـ keychain |
| `lib/core/cloud/cloud_backup_state.dart` | حالة النسخ في ملف `cloud_backup.json` جنب `pos.db` |
| `lib/core/cloud/cloud_backup_service.dart` | المؤقت، وقرار إمتى يرفع، والرفع نفسه |
| `lib/core/cloud/pending_restore.dart` | تجهيز الاسترجاع وتطبيقه أول ما البرنامج يفتح |
| `lib/features/settings/cloud_backup_screen.dart` | الشاشة (الإعدادات ← الخادم ← النسخ الاحتياطي السحابي) |

**ليه الحالة في ملف مش في الداتابيز؟** أي كتابة في `pos.db` بتغيّر النسخة الجاية، فالجهاز
الواقف كان هيرفع نسخة جديدة كل ساعة. وكمان الاسترجاع ميجيبش معاه ربط جهاز تاني.
وللسبب ده، الرفع الناجح مبيكتبش في `audit_log`. الفشل بس هو اللي بيتسجل، ومرة واحدة لكل سبب.

### الربط

1. السيرفر بيدي **كود ربط** للمحل (كود واحد لكل الأجهزة).
2. على الجهاز: الإعدادات ← الخادم ← النسخ الاحتياطي السحابي، وتكتب عنوان السيرفر وكود الربط، وتدوس "ربط".
3. أول جهاز: بيعمل المفتاح وبيرفع أول نسخة على طول. **اعرض المفتاح واكتبه.**
4. أي جهاز بعده: هيطلب منك تكتب مفتاح المحل.

### الاسترجاع

1. من نفس الشاشة: "استرجاع من السحابة"، تختار النسخة، وتكتب المفتاح لو مش محفوظ على الجهاز.
2. النسخة بتتفك وتتراجع، وبعدين بتتحط جنب `pos.db` باسم `pos.db.restore`.
3. تقفل البرنامج وتفتحه: قبل ما الداتابيز تتفتح، القديمة بتتنقل لـ
   `pos.db.before-restore-<الوقت>` (**ومبتتمسحش**)، والجديدة بتاخد مكانها.
4. مفتاح الداتابيز القديم بيتحفظ في الـ keychain باسم `db_key_before_restore`، علشان لو حصل استرجاع بالغلط.

> **تنبيه:** الجهاز اللي بيسترجع بياخد هوية الجهاز صاحب النسخة (device id). ده المطلوب لما
> بتبدّل جهاز باظ، لكن **متشغلش الجهازين مع بعض** على نفس الشبكة.

## السيرفر (`cloud/`)

TypeScript وFastify وPrisma وPostgreSQL، وجوه Docker. التفاصيل في `cloud/README.md`.

- النسخ ملفات على الديسك (volume اسمه `posbackup_backups`)، والبيانات الوصفية في Postgres.
- كود الربط والتوكن متخزنين sha256 بس.
- **الاحتفاظ:** آخر 48 ساعة كلها، وبعدها نسخة لكل يوم لمدة 30 يوم، ونسخة لكل شهر لمدة سنة،
  ونسخة لكل سنة بعد كده. آخر نسخة لأي جهاز مبتتمسحش أبداً.

### النشر الحالي

| | |
| --- | --- |
| العنوان | `https://posbackup.91.99.195.177.sslip.io` |

عمل محل جديد:

```sh
cd /opt/posbackup
docker compose exec api node dist/scripts/create-shop.js "اسم المحل"
docker compose exec api node dist/scripts/list-shops.js
```

العنوان ده مكتوب افتراضياً في الشاشة. لو السيرفر اتغير (دومين حقيقي مثلاً)، ابني بـ:
`--dart-define=CLOUD_BACKUP_URL=https://العنوان-الجديد`

## ملاحظات أمان معروفة

- على Windows، `pos.db` **مش متشفرة فعلياً** (SQLCipher مش شغال على Windows، رغم إن الكود بيبعت
  `PRAGMA key`). النسخة السحابية متشفرة بمفتاح الاسترجاع بغض النظر عن ده.
- مفتاح الداتابيز بيسافر جوه النسخة المتشفرة، علشان الاسترجاع على جهاز جديد يشتغل.
  الاسترجاع من Windows لـ Android (أو العكس) **مش مضمون**، لأن الداتابيز على Windows مش متشفرة
  وعلى Android متشفرة.
